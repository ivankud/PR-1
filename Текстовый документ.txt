Мне нужно спланировать визуальный редактор сценарной логики для rest-концепции с преобразованием в код.
Основные положения:
1. код размещается в схемах БД PostgreSQL, на языке pl/pgsql
2. есть есть основные функции get, post, put, delete
3. post, put на входе имеют json c изменяемыми атрибутами
3. создание записей происходит в post через метод insertrecord, который просто вставляет запись в таблицу с инкрементальным 
4. остальные атрибуты записи редактируются через методи settableattribute
5. settableattribute вызывает методы dobeforeset, непосредственный update атрибута, doafterset
6. put снимает копию начальной версии строки и передает ее внутрь settableattribute, dobeforeset, doafterset
7. в конце вызывается afteredit




Уточнение по методоу settableattribute:
есть еще один атрибут old_record - старая версия строки, необязательный атриубут, берется в начале транзакции через метод getRow через record_id.
DO BEFORE SET это тоже метод dobeforeset, он реализован не через триггер.принимает также атрибуы record_id, attribute_name, new_value, old_record. 
атрибут new_value имеет специфику InOut
DO AFTER SET это тоже метод doafterset, он реализован не через триггер.принимает также атрибуы record_id, attribute_name, old_record.
Наверное неправильно выразился мне нужен редактор сценарной логики для выстраивания логики изменения атрибутов объекта по условиям с сравниванием условий и значений связанных объектов или прошлых или текущих значений атрибутов объектов системы, выстраивать логику, проверки и взаимосвязи объектов между собой. при этом сохраняя использование описанных выше методов.
в большинстве своем я планировал использовать в описанных методах констркуции GET, POST, PUT, DELETE, IF/ELSE, LOOP, VARIABLES.

2. Должны ли nodes иметь условную логику (IF/ELSE) внутри? - да должны
3. Как обрабатывать переменные между узлами? (через global context?) нет, описанных выше аргументов должно хватить
4. Нужна ли валидация JSON schema для attributes?
