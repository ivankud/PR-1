# Архитектурные решения

## 1. Управление состоянием: React Context + useReducer

**Решение:** Использовать React Context с useReducer вместо Redux или MobX.

**Причины:**
- Проект небольшой, нет необходимости в дополнительных зависимостях
- useReducer даёт предсказуемое управление состоянием
- История (undo/redo) реализована вручную в reducer

## 2. Хранение форм в public/forms/

**Решение:** Формы хранятся как JSON-файлы в `public/forms/`, манифест — `index.json`.

**Причины:**
- Простота редактирования без БД
- Возможность версионирования через git
- Быстрая загрузка через fetch

## 3. Шаблоны примитивов в public/primitives/

**Решение:** Шаблоны примитивов хранятся как JSON-файлы в `public/primitives/`.

**Причины:**
- Расширяемость: новый примитив = новый JSON-файл
- Отделение данных от кода
- Возможность редактирования без пересборки

## 4. История до 100 состояний

**Решение:** Ограничить историю undo/redo до 100 состояний.

**Причины:**
- Предотвращение утечки памяти
- Достаточно для типичных сценариев редактирования

## 5. `*_LIVE` действия не пишут в историю

**Решение:** Действия `MOVE_PRIMITIVES_LIVE` и `RESIZE_PRIMITIVE_LIVE` не пишут в историю, только `isDirty: true`. После завершения drag/resize вызывается `COMMIT_HISTORY`.

**Причины:**
- Предотвращение засорения истории промежуточными состояниями
- Оптимизация производительности при перетаскивании

## 6. Компиляция функций через new Function

**Решение:** Пользовательские функции компилируются через `new Function('context', code)`.

**Причины:**
- Простота реализации
- Полный доступ к JavaScript
- Изоляция через параметр `context`

## 7. Якоря {{path}} с многопроходной подстановкой

**Решение:** Подстановка `{{path}}` выполняется многопроходно (до 10 проходов).

**Причины:**
- Поддержка вложенных шаблонов (шаблон, ведущий к другому шаблону)
- Гибкость при построении динамических значений

## 8. Basic Auth в localStorage

**Решение:** Учётные данные хранятся в localStorage в Base64.

**Причины:**
- Простота реализации
- Не требуется серверная часть
- Base64 — лёгкое кодирование (не шифрование)

## 9. Чистый CSS без фреймворков

**Решение:** Использовать чистый CSS без CSS-фреймворков.

**Причины:**
- Минимум зависимостей
- Полный контроль над стилями
- Простота поддержки

## 10. AG Grid для таблиц

**Решение:** Использовать AG Grid для компонента таблицы (`AGTable.js`).

**Причины:**
- Мощный функционал таблиц
- Поддержка событий и данных
- Единственная сторонняя UI-библиотека (кроме React Router)

## 11. Хранилище функций в public/functions/

**Решение:** Функции можно сохранять в библиотеку как JSON-файлы в `public/functions/` (манифест — `index.json`, формат каждого файла `{ name, description, code }`) и импортировать в форму независимой копией.

**Причины:**
- Переиспользование функций между формами без копирования кода вручную
- Аналогично формам: простота, версионирование через git, загрузка через fetch
- Импорт создаёт независимую копию (новый id, суффикс имени при конфликте), изменения в форме или хранилище не влияют друг на друга

## 12. Источник данных AGTable "function"

**Решение:** AGTable поддерживает три источника данных: `manual`, `api`, `function`. При `dataSource = "function"` данные получает пользовательская функция формы (свойство `functionName`), которой передаётся контекст формы и активные фильтры примитива.

**Причины:**
- Гибкость: функция может сама выполнять GET к серверу (в т.ч. с авторизацией через `fetchWithAuth`), используя контекст и фильтры
- Фильтры передаются функции как `context.filters`, `context.filterModel`, `context.activeFilters`
- Функция возвращает массив строк или объект с обёрткой (`data`/`rows`/`items`/`records`/`content`)
- Глобальный хелпер `fetchWithAuth` добавляет Basic Auth из localStorage к запросам функций
- **Пагинация:** при `serverPagination: true` AGTable передаёт функции `context.currentPage`/`context.page` и `context.pageSize`/`context.size` (и `context.serverPagination`), а изменение страницы/размера перезапускает вызов функции. Функция должна сама добавить параметры `page`/`size` к своему GET и, для корректной блокировки «Вперёд», вернуть объект с `total` (массив строк при обёртке — в `content`)
